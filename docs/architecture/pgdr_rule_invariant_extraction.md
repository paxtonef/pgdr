# PGDR Rule / Invariant Extraction (P2)

**Zero behavior change.** This document maps what PGDR actually does, as
verified by reading every domain model, application service, port,
adapter, config file, and test in the repository — not what README files,
YAML comments, or docstrings claim it does. Where a comment cites a rule ID
(e.g. `PGDR-BR-001`), that citation is treated as a **claim to verify**,
not as evidence of enforcement.

Method, per rule: `DECLARED? → IMPLEMENTED? → CALLED? → ENFORCED? → TESTED?`
A rule is only classified `ENFORCED` if all five hold. See
`p2_findings.md` for the synthesis and the ten most important discoveries.

## Enforcement status legend

| Status | Meaning |
|---|---|
| `ENFORCED` | Implemented, invoked, and effective on the relevant path. |
| `PARTIAL` | Some paths/fields enforced, others not. |
| `DORMANT` | Implementation exists but is never invoked on any reachable path. |
| `UNENFORCED` | Declared, but no effective enforcement exists. |
| `MISSING` | Expected by an explicit contract/invariant; neither declaration nor implementation exists. |
| `ACCIDENTALLY SATISFIED` | True today only because a feature it depends on doesn't exist yet — not because it's actually enforced. |
| `N/A` | Exists conceptually, outside current executable scope. |
